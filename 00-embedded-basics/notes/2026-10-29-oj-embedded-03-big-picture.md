# 2026-10-29 OJ 임베디드 입문 3강: 큰 그림을 그려보자

출처: OJ Tube 「입문자를 위한 임베디드 개발강의(편집본)」 3강

## 오늘 배운 것 (3줄)
- 개발자는 모든 분야를 다 공부할 수 없으므로, 먼저 전체 개발 맵(뼈대)을 세우고 연차가 쌓이며 디테일을 채워 나가야 한다.
- 컴퓨터는 아래에서부터 전기 → 반도체·트랜지스터(전류가 흐르면 1, 안 흐르면 0) → CPU(0과 1로 계산) → 메모리·저장장치와 결합한 컴퓨터 순으로 쌓인다.
- MCU는 ARM 등이 설계한 CPU 코어에 메모리·플래시·GPIO 같은 주변 장치를 한 칩에 합친 것이고, 임베디드는 범용 PC와 달리 특정 목적(온도 측정, 체중계 등)에 특화된 장치다.

## 계층 정리
```
자연 (원자·전자·전기)
  └─ 전기: 발전소 → 220V 교류 → 기기가 필요한 전압으로 변환해 사용
      └─ 반도체·트랜지스터: 0과 1 표현
          └─ CPU: 연산 장치 + 레지스터
              ├─ 범용 컴퓨터: CPU + 램 + 저장장치 (여러 목적)
              └─ MCU: CPU 코어 + 메모리 + 플래시 + GPIO 등을 한 칩에 (특정 목적 → 임베디드)
```

## 내 보드에 적용해 보기
- Nucleo-F411RE의 STM32F411은 ARM Cortex-M4 코어(ARM 설계)에 ST가 플래시 512KB, GPIO, UART, I2C, SPI, ADC 등을 붙인 MCU다.

## 면접 예상 질문

### Q1. CPU와 MCU의 차이는 무엇인가요?

**30초 답변**
> CPU는 명령어를 해석하고 연산하는 처리 장치 자체이고, 혼자서는 동작할 수 없어 외부에 메모리와 주변 장치를 붙여야 합니다. MCU는 CPU 코어에 플래시, SRAM, GPIO, 타이머, UART 같은 주변 장치를 한 칩에 넣은 것이라 칩 하나로 기기를 제어할 수 있습니다. 그래서 MCU는 작고 싸고 전력을 적게 써서 특정 기능을 하는 임베디드 기기에 주로 쓰입니다.

**상세 설명**

| 구분 | CPU | MCU |
| --- | --- | --- |
| 구성 | 연산 장치(ALU), 제어 장치, 레지스터 | CPU 코어 + 플래시 + SRAM + 주변 장치(GPIO, 타이머, UART, I2C, SPI, ADC 등) |
| 메모리 | 외부 RAM, 저장장치 필요 | 칩 안에 내장 (보통 KB~수 MB) |
| 성능 | 높음 (GHz급, 복잡한 OS 구동) | 낮음 (수십~수백 MHz) |
| 전력·가격 | 높음 | 낮음 |
| 소프트웨어 | Windows, Linux 등 범용 OS | OS 없이(베어메탈) 또는 RTOS |
| 예시 | PC의 Intel·AMD 프로세서 | STM32, AVR(아두이노), ESP32 |

- 내 보드 예시: STM32F411RE는 ARM이 설계한 Cortex-M4 코어(최대 100MHz)에 ST가 플래시 512KB, SRAM 128KB, GPIO, UART, I2C, SPI, ADC, 타이머 등을 붙여 만든 MCU입니다.
- ARM은 CPU 설계도(IP)만 팔고, ST·NXP·TI 같은 회사가 그 코어에 자기 주변 장치를 붙여 칩을 만듭니다. 그래서 같은 Cortex-M4라도 회사마다 주변 장치와 레지스터 구성이 다릅니다.

**꼬리 질문 대비**
- *MPU(또는 AP)와 MCU는 어떻게 다른가요?* → MPU는 Cortex-A처럼 성능이 높은 코어에 외부 DRAM을 붙이고 리눅스 같은 OS를 올려 쓰는 칩입니다(라즈베리파이). MCU는 메모리를 내장하고 실시간 제어에 강합니다. 실제 장비에서는 MPU가 화면·네트워크를, MCU가 센서·모터 제어를 나눠 맡는 경우가 많습니다.
- *Cortex-M과 Cortex-A의 차이는?* → Cortex-M은 MCU용으로 저전력·빠른 인터럽트 응답(실시간성)에 맞춰져 있고 MMU가 없습니다. Cortex-A는 고성능 애플리케이션용으로 MMU가 있어 리눅스 같은 OS를 돌릴 수 있습니다.
- *왜 PC처럼 그냥 CPU를 쓰지 않나요?* → 부품 수, 크기, 전력, 비용이 늘어나고, 범용 OS는 응답 시간을 보장하기 어렵기 때문입니다.

### Q2. 임베디드 시스템과 범용 컴퓨터의 차이는 무엇인가요?

**30초 답변**
> 범용 컴퓨터는 사용자가 프로그램을 바꿔 가며 문서 작업, 게임, 인터넷 등 여러 목적에 쓰는 장치입니다. 임베디드 시스템은 온도 조절기나 체중계처럼 특정 기능을 하도록 하드웨어와 소프트웨어가 함께 설계된 장치입니다. 그래서 임베디드는 제한된 메모리와 전력 안에서 동작해야 하고, 정해진 시간 안에 반응하는 실시간성과 오래 멈추지 않는 신뢰성이 중요합니다.

**상세 설명**

| 구분 | 범용 컴퓨터 | 임베디드 시스템 |
| --- | --- | --- |
| 목적 | 여러 목적, 사용자가 프로그램 설치 | 특정 목적에 특화 |
| 자원 | 넉넉한 CPU·메모리·저장장치 | 제한된 메모리·전력·비용 |
| OS | Windows, macOS, Linux | 없음(베어메탈), RTOS, 임베디드 리눅스 |
| 시간 요구 | 평균 성능이 중요 | 정해진 시간 안에 응답(실시간성) |
| 신뢰성 | 재부팅 가능 | 수년간 무정지 동작이 요구되는 경우가 많음 |
| 입출력 | 키보드, 마우스, 모니터 | 센서, 모터, 버튼, LED, 통신 |
| 예시 | PC, 노트북 | 리모컨, 세탁기, 자동차 ECU, 고추 건조기 제어 보드 |

- 강의의 고추 건조기 예시: 온도 센서로 온도를 읽고 설정 온도(예: 80도)에 도달하면 히터를 끄는 한 가지 일만 합니다. 이 기능을 위해 필요한 하드웨어만 넣고 그에 맞는 펌웨어를 올린 것이 임베디드 시스템입니다.
- 실시간성은 "빠르다"가 아니라 "정해진 시간을 반드시 지킨다"는 뜻입니다. 에어백처럼 늦으면 실패인 경우를 하드 실시간, 동영상 재생처럼 가끔 늦어도 되는 경우를 소프트 실시간이라고 합니다.

**꼬리 질문 대비 (방산 지원 시)**
- *방산 임베디드는 일반 임베디드와 무엇이 다른가요?* → 고온·저온·진동 같은 혹독한 환경에서도 동작해야 하고, 실시간성과 신뢰성 요구가 훨씬 엄격하며, 장비를 수십 년 운용하므로 유지보수성과 문서화가 중요합니다.
- *스마트폰은 임베디드인가요?* → 하드웨어는 임베디드 기술로 만들어졌지만 사용자가 앱을 설치해 여러 목적에 쓰므로 범용 컴퓨터에 가깝습니다. 경계가 흐려지고 있다는 점까지 말하면 좋습니다.
- *임베디드 리눅스와 RTOS는 언제 쓰나요?* → 네트워크·화면·파일 시스템 등 기능이 많으면 임베디드 리눅스, 엄격한 시간 보장과 적은 자원이 중요하면 RTOS를 씁니다. (7주차 FreeRTOS, 9~10주차 리눅스에서 자세히 정리 예정)
